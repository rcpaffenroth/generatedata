# The whest datasets

Weight-space estimation data for the **ARC White-Box Estimation Challenge 2026**:
given only the weights of a deep ReLU MLP, predict the mean activation of its
layers under a standard normal input.

## The problem

Write one network's forward map as a product of nonlinear layers,

    z_0 = x,        z_l = relu(z_{l-1} W_l),        l = 1 .. depth,

and the target is the deterministic functional

    F(W) = E_{x ~ N(0, I_width)} [ z_depth ]   in R^width

together with its per-layer counterparts. The input distribution is integrated out,
so `F` is a function of `W` alone — a map `R^(depth × width × width) → R^width`.

As a dynamical system each network is a product of random matrices acting on a
distribution, and `F(W)` is a functional of its terminal distribution. The heavy
tail of `F` across random `W` is not noise: it is the large-deviation statistics of
the finite-time Lyapunov exponent, some products expanding and some contracting.

Competition conventions, all reproduced exactly here:

| | |
|---|---|
| weights | iid `N(0, 2/width)` — He initialisation at fan-in `width` |
| biases | **none** |
| forward | `z ← relu(z @ W_l)` — note `@W`, ***not*** `@W.T` |
| relu | applied at **every** layer, including the last |
| dtype | float32 weights; ground truth accumulated in float64, TF32 off |

The forward convention is not a style choice. Propagating the officially published
weights as `z @ W` reproduces the official means to within Monte-Carlo noise
(max abs error 9.8e-5 at our MC standard error of ~5e-5); `z @ W.T` is wrong by
**3.3** — an O(1) error, not a subtle one.

## The ladder

Eight datasets at ≤100 MB, plus two at ≤500 MB. All ten are on disk once
`--whest-xl` has run; sizes below are measured, not estimated.

| `whest_w256_d8` | 256 | 8 | 45 | 94.8 MB | official, 1e9 | 1.7e-10 | 1.3e-4 | 0.002 | 751,000× |
| `whest_w16_d8` | 16 | 8 | 10,000 | 88.3 MB | ours, 2²⁴ | 1.9e-8 | 1.4e-3 | 0.065 | 73,400× |

| `whest_w128_d32_xl` | 128 | 32 | 224 | 473.7 MB | ours, 2²⁴ | 4.4e-9 | 1.1e-4 | 0.233 | 23,800× |

*Total 1,622 MB. Only `whest_w8_d8` is generated by default; the rest are opt-in.*

**Headroom** is `ut_final_layer_mse / label_mc_se2` — how far the labels sit below
the baseline they are meant to measure. Even the weakest rung has 1,440× margin, so
no rung is label-noise-limited.

### Why this shape

**Depth is the regime variable; width is merely the dimension.** The fraction of
coordinates with `F_j = 0` *exactly* depends almost entirely on depth:

| depth | w32 | w64 | w128 | w256 |
|---|---|---|---|---|
| 8 | 4.9% | 3.2% | 2.4% | 2.2% |
| 16 | 18.3% | 14.8% | 12.4% | 11.7% |
| 32 | 33.0% | 29.7% | 26.8% | 25.1% |

(Measured at 2¹⁶ draws, so these are upper bounds — they flag activation
probability < 1.5e-5, where the official 1e9-sample bake flags < 1e-9. Multiply by
~0.7 for true deadness: at 256×32 this table says 25.1% where the official labels
say 17.84%.)

The ReLU cone's per-layer survival probability self-averages as width grows; only
narrow networks die faster, from finite-size fluctuations. So the ladder **holds
depth at the competition's 32 and sweeps width**, with a depth-8 branch to isolate
depth at fixed width. That gives a five-point width sweep in the competition
regime, and the depth 8-vs-32 contrast twice — at width 256 with official labels on
both ends, and at width 16.

**Width 8 at depth 32 is deliberately absent**: roughly half its coordinates and 5%
of whole networks are dead, which makes the target degenerate. Width 16 is the
narrowest that keeps every network alive at depth 32 — at width 2 and depth 32,
*every* network is dead, and because relu is positively homogeneous no
initialisation rescaling revives it.

### Choosing a rung

| you want to | use |
|---|---|
| train something (10,000 networks) | `whest_w16_d8`, `whest_w8_d8` |
| train in the competition regime | `whest_w16_d32` (2,700), `whest_w32_d32` (701) |
| evaluate at competition width | `whest_w256_d32_xl` (56), `whest_w128_d32_xl` (224) |
| study width scaling at fixed depth | the five `*_d32` rungs |
| study depth at fixed width | `whest_w256_d8` vs `whest_w256_d32`; `whest_w16_d8` vs `whest_w16_d32` |
| a properly powered 256×32 benchmark | **not these** — pull the 1,000-network official split from the Hub |

## Usage

The whest family is reachable **only** through `load_data_as_sequence`. It has no
flat DataFrame form: `load_data` and `load_data_as_xy` raise a `ValueError` naming
the function to use instead. Nothing is in the remote snapshot yet, so pass
`local=True`.

```python
from generatedata.load_data import load_data_as_sequence

# One weight matrix per timestep, in layer order.  default_step_size is width**2,
# so step_size can be omitted.
W_seq, F = load_data_as_sequence('whest_w256_d32', local=True)
# W_seq : (11, 32, 65536) float32 memmap
# F     : (11, 256)       ground-truth final-layer means

W = W_seq.reshape(-1, 32, 256, 256)      # (nets, depth, width, width)
```

Local arrays are **memory-mapped**, so that costs no RAM until you index into it —
important for the 471 MB rungs. Call `np.asarray(W_seq)` if you want it resident.

### The cheap baseline and the residual

```python
_, ut_fixed = load_data_as_sequence('whest_w256_d32', local=True, part='start')
residual = F - ut_fixed          # R(W) = F(W) - UT_fixed(W)
```

`ut_fixed` is a fixed-quadrature unscented transform: the `2·width` sigma points
`±r·e_i` (the rows of `[r I; -r I]`) at shell radius

    r = E||x|| = sqrt(2)·Γ((width+1)/2)/Γ(width/2)

propagated through the network and averaged. The radius is the *first* radial
moment, which is the right one because relu chains are positively homogeneous of
degree one — `F(c x) = c F(x)` — so `sqrt(width)` would introduce a
`1 + 1/(4·width)` bias that compounds with depth. Because no random rotations are
used, `UT_fixed` and hence `R` are **deterministic functions of `W`**: correcting
the baseline is a well-posed regression problem, not a variance-reduction problem.

### Per-layer means

```python
_, all_layers = load_data_as_sequence('whest_w256_d32', local=True, part='all_layers')
# (11, 32, 256);  all_layers[:, -1] is exactly F
```

> ⚠️ **Per-layer means are labels, never inputs.** The estimator contract hands
> `predict(mlp, budget)` only `width`, `depth`, `weights`, `seed` and `name` — no
> means of any kind — and requires it to *return* the `(depth, width)` stack. Being
> *given* the per-layer means would collapse 32 layers of error compounding into
> one and gut the problem. They are legitimate as a deep-supervision target (the
> contest asks you to predict them, and reports `all_layers_mse`); they are never a
> feature.
>
> This is enforced: `load_data_as_sequence` **refuses `label_every_step=True`** for
> this family, since that would concatenate the labels onto every timestep of the
> features. The default resolves to `False`, so the safe thing happens silently and
> the unsafe thing raises.

### A training loop

```python
import numpy as np, torch
from generatedata.load_data import load_data_as_sequence

class WhestDataset(torch.utils.data.Dataset):
    """Weights in, final-layer means out.  Rows page in from the memmap on demand."""

    def __init__(self, name, part='target'):
        self.W_seq, self.y = load_data_as_sequence(name, local=True, part=part)
        info_dim = int(round(self.W_seq.shape[2] ** 0.5))
        self.shape = (self.W_seq.shape[1], info_dim, info_dim)   # (depth, width, width)

    def __len__(self):
        return self.W_seq.shape[0]

    def __getitem__(self, i):
        # np.array() copies out of the read-only memmap, which torch requires.
        W = torch.from_numpy(np.array(self.W_seq[i], dtype=np.float32)).view(self.shape)
        return W, torch.from_numpy(np.array(self.y[i], dtype=np.float32))

train = torch.utils.data.DataLoader(WhestDataset('whest_w16_d8'), batch_size=64,
                                    shuffle=True, num_workers=2)
for W, F in train:
    # W : (batch, depth, width, width)      F : (batch, width)
    ...
```

Train in `log1p(F)` space if you like — `F` is a heavy-tailed product of per-layer
gains — but **report raw MSE**, since that is what the contest scores. `R²` on log
targets flatters by about three orders of magnitude.

### Scoring an estimator on a rung

```python
import numpy as np
from generatedata.load_data import load_data_as_sequence

W_seq, F = load_data_as_sequence('whest_w256_d32_xl', local=True)
W = np.asarray(W_seq).reshape(-1, 32, 256, 256)

pred = my_estimator(W)                            # (nets, 256)
final_layer_mse = ((pred - F) ** 2).mean(axis=1).mean()   # scored exactly this way
```

The contest's leaderboard metric is this MSE times a compute multiplier
`max(0.1, C/B)`; these datasets carry no FLOP accounting, so they measure the
accuracy half only.

## Facts that bite

- **`@W`, not `@W.T`.** Getting this backwards costs a factor of ~3 in the output,
  not a rounding error. At depth 1 the exact answer is
  `F_j = ‖W[:, j]‖ / sqrt(2π)` — the **column** norm, which is the cheapest way to
  test your convention (the transposed convention gives the row norms).
- **Feed `Wᵀ` to a mean-propagating model.** Since the forward is `z @ W`, the mean
  operator is `Wᵀ`: `E[(zW)_j] = Σ_i m_i W_ij = (Wᵀ m)_j`. A model whose per-layer
  message is meant to be the mean operator should therefore receive the transpose.
- **About a fifth of the target coordinates are exactly zero** at 256×32 (17.84% in
  the official labels, with a billion samples). Deadness is a *cone* property — the
  reachable set of the relu chain lies in the halfspace `(z W_final)_j ≤ 0` — so any
  point-propagation estimator gets those coordinates exactly right for free. The UT
  baseline scores **exactly 0.0** error on them, meaning 100% of its error lives on
  the ~82% live coordinates. A model that regresses `F` directly, however, must
  *learn* those zeros, and pays in raw MSE for every small nonzero it emits there.
- **The tail is per-coordinate, not per-network.** In the official split the
  per-network mean of `F` spans only 3.1× (median 0.426, max 1.30), while individual
  coordinates reach 9.7 against an overall mean of 0.50.
- **Mass concentrates as depth grows.** Over the official 32 layers the mean over
  all coordinates decays 0.564 → 0.502 while the mean over *surviving* coordinates
  rises 0.564 → 0.611: the dynamics conserve mass while shrinking the support.
- **Small N wobbles a lot.** The same fixed-UT baseline scores 2.837e-5 on the
  11-network rung, 4.340e-5 on the 56-network rung, and 4.263e-5 over all 100
  official networks. Eleven networks give ~30% standard error on a measured MSE, 56
  give ~13%, 224 give ~7%. Each dataset carries a `statistical_note` saying so.
- **TF32 must be off** whenever you compute ground truth: it truncates matmul inputs
  to 10 mantissa bits, a ~1e-3 relative error per layer, which swamps everything
  these labels are trying to resolve.

## Storage

Each dataset is a set of plain `.npy` arrays (`storage: "npy"` in its metadata):

```
<name>_weights.npy          (num_points, depth, width, width)  float32
<name>_all_layer_means.npy  (num_points, depth, width)         float32
<name>_final_means.npy      (num_points, width)                float32
<name>_ut_fixed.npy         (num_points, width)                float32
<name>_info.json
<name>_mlp_ids.npy          (num_points,)  int32   ] official rungs only
<name>_mlp_seeds.npy        (num_points,)  int64   ]
```

`final_means` duplicates `all_layer_means[:, -1]` exactly, as the official data
does; it costs `4·width` bytes per row and saves every consumer an indexing rule.
Total size is

    bytes = 4 × (depth·width² + depth·width + 2·width) × num_points

which is what fixes each rung's `num_points`, and which `whest_dataset_bytes()`
computes. Every dataset above matches it to 0.0 MB.

### Why not the library's flat parquet format

Every other dataset here stores one scalar parquet column per feature. A whest row
holds `depth × width²` weights — 2,097,152 at the competition geometry — and
parquet spends **~570 bytes per column** on page headers, column-chunk metadata and
the column name, a cost per *column* that is independent of the number of rows:

    file_bytes ≈ columns × (4…5 × num_points + 570)

So the column count, not the sample count, sets the file size, and **cutting
`num_points` buys almost nothing**: a 100 MB file is exhausted by ~175,000 columns
with *zero* rows. Past ~262,000 columns there is a harder wall — pyarrow writes the
file and then cannot read it back (`TProtocolException: Exceeded size limit` while
deserialising the schema) — so an oversized dataset looks fine until something
loads it.

Compression is no escape: He weights are maximum-entropy for their variance.

| method | ratio |
|---|---|
| zlib -6 / -9 | 0.929× |
| lzma | 0.923× |
| byte-shuffle + zlib | 0.853× |
| byte-shuffle + lzma | **0.845×** (best) |
| fp16 cast | 0.500×, but ~5e-4 relative error — fatal at these scales |

Nor can the weights be compressed to a seed: the official `mlp_seed` does **not**
control weight sampling (it is a separate stream for the *estimator's* own
randomness), so the published weights are irreducible data.

Hence `.npy`, which also memory-maps, and sequence-only access — which is the honest
framing anyway: the forward pass is an *ordered* product of operators, so the layer
axis is a sequence axis, not an exchangeable feature axis. Each array is written to
a `.partial` file and renamed only on success, so an interrupted write cannot leave
a truncated file that looks present.

## The official competition data

Four of the ten rungs are not generated at all — they are the organisers' own
published networks, from
[`aicrowd/arc-whestbench-public-2026`](https://huggingface.co/datasets/aicrowd/arc-whestbench-public-2026),
pinned to commit hashes rather than tags. Their labels are ground truth at
**1,000,000,000 samples per network**, a noise floor of ~5e-11 that nothing bakeable
locally approaches, which makes them the ladder's reference rungs.

Upstream there are three datasets across two immutable tags:

| revision | geometry | splits | parquet |
|---|---|---|---|
| `v1-warmup` | 256×**8** | mini 100, full 1000 | 212 MB + ~4.4 GB |
| `v1-phase1` | 256×**32** | mini 100, full 1000 | 860 MB + 8.6 GB |

All four of our official rungs are carved from the **`mini`** splits using disjoint
row ranges (`whest_w256_d32` takes rows 0–10, `whest_w256_d32_xl` rows 11–66), which
keeps our datasets mutually disjoint while needing ~1.07 GB of download instead of
the 8.6 GB `full` split. All 1,100 published networks are iid draws, so row ranges
within `mini` are as independent as crossing splits would be.

`mlp_id`, `mlp_seed` and `mlp_name` are preserved for traceability back to the
published rows. The data is **CC-BY-4.0**; the required attribution is recorded in
each dataset's metadata as `source_repo`, `source_revision`, `source_tag`,
`source_split`, `source_rows`, `license` and `homepage`.

Two upstream documentation errors worth knowing: the docs describe `weights` as
float64 (they are float32), and quote `avg_variance ≈ 0.18` giving a ground-truth
floor of 2e-10 — that is the *warmup* figure. At phase-1 the variance is 0.050, so
the floor is ~5e-11.

For context on what that ground truth cost: the bake metadata records **420 s and
4.2e15 FLOPs per network**, i.e. roughly 117 GPU-hours for the 1,000-network split,
on A100/3090 pods with full determinism flags set.

## Generating

```bash
# The eight-dataset grid: ~680 MB, ~1 GB downloaded, ~40 min on a GPU
uv run python scripts/generatedata_local.py --whest

# Also the two 500 MB datasets (implies --whest)
uv run python scripts/generatedata_local.py --whest-xl
```

Or from Python:

```python
from generatedata.whest_generators import generate_whest_all
generate_whest_all('data/processed', include_xl=True)
```

Both print a preflight summary of every dataset, its size and the total before
writing anything, and skip datasets that already exist with matching parameters, so
re-running only fills in what is missing.

This tier is **opt-in** and is *not* part of `--all`: unlike the rest of the
library it wants a GPU worth using, downloads about a gigabyte from the HuggingFace
Hub, and writes 1.6 GB. Only `whest_w8_d8` is built by a plain `generate_all`,
deliberately — it keeps the `.npy` storage path and its loader guards under test on
every run, and its smaller Monte-Carlo budget (2¹⁸ draws, ~20 s on a GPU, ~10 min
CPU-only) is what a test-session fixture can afford.

Individual pieces, if you want a geometry that is not on the ladder:

```python
from pathlib import Path
from generatedata.whest_generators import (generate_whest, generate_whest_official,
                                           he_weights, mc_layer_means,
                                           ut_fixed_final_mean, whest_dataset_bytes)

generate_whest(Path('data/processed'), width=32, depth=16, num_points=500)
generate_whest_official(Path('data/processed'), key='phase1', num_points=11)

whest_dataset_bytes(256, 32, 56)          # 471_711_744 -- check before you commit
W = he_weights(100, 32, 16, seed=0)       # competition-faithful networks
means, second = mc_layer_means(W, 1 << 20, seed=1, device='cuda')
ut = ut_fixed_final_mean(W, device='cuda')
```

`mc_layer_means` returns second moments alongside the means, so the labels' own
standard error is `sqrt((second - means²) / mc_samples)` — always check it against
the effect you are trying to measure.

## Metadata reference

Every whest `info.json` carries:

| key | meaning |
|---|---|
| `storage` | `"npy"` — not a flat parquet pair |
| `data_family` | `"whest"` |
| `source` | `"generated"` or `"official:phase1"` / `"official:warmup"` |
| `width`, `depth` | geometry |
| `num_points` | number of networks |
| `x_y_index`, `x_size` | `depth·width²`, the feature count |
| `y_size` | `width`, the label count |
| `default_step_size` | `width²`, so one timestep is one weight matrix |
| `onehot_y` | `0` — this is regression |
| `label_every_step_allowed` | `False` — broadcasting labels would leak the target |
| `forward_convention` | `"z <- relu(z @ W_l), no biases"` |
| `flatten_order` | `"layer-major: W[layer, row, column]"` |
| `mc_samples` | draws per network behind the labels |
| `label_mc_se2` | measured label noise (variance), the resolution floor |
| `ut_final_layer_mse` | raw MSE of the `ut_fixed` baseline — the number to beat |
| `dead_coordinate_fraction` | share of coordinates with `F_j = 0` exactly |
| `dead_network_fraction` | share of networks with `F ≡ 0` (0.00 on every rung here) |
| `seed` | generated rungs only |
| `source_repo`, `source_revision`, `source_tag`, `source_split`, `source_rows`, `license`, `homepage`, `mlp_names`, `statistical_note` | official rungs only |
